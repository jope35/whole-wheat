# Plan 4 — Eval and MLflow

Spec: `docs/superpowers/specs/2026-08-25-whole-wheat-design.md`  
Depends on: Plan 3 `EvidencePackage` contract only  
Produces: hit@k, eval notebook, MLflow metrics

Do not score parent answers. Do not call the parent.

## Goal

A reader runs `notebooks/04_eval.py` on frozen questions. The notebook prints hit@5 and hit@10 and writes one MLflow run per question.

## Files

- `databricks.yml` — eval notebook task, MLflow experiment name variable
- `src/whole_wheat/eval.py` — `fetch`, `hit_at_k`, `run`
- `data/qids.json` — `[]` until you freeze ids in the live fetch cell
- `notebooks/04_eval.py`
- `tests/test_eval_contract.py`

## Tasks

1. `hit_at_k(ranked, gold_source_files, k)` → bool. A hit is `ranked[i].source_file` in the gold list for `i < k`.
2. `eval fetch`: gated CSV → gitignored `data/eval.json` with `id`, `query`, `source_files` only. No `answer` field.
3. `eval run`: for each qid, run the searcher, score hit@5 and hit@10, log MLflow (`qid`, hits, `rounds`, `tool_calls`). If MLflow fails, print a warning and still print the table.
4. Notebook: fetch (optional, needs `HF_TOKEN`) → run → `display` the table.
5. Freeze `qids.json` during the first successful live fetch. After that, treat it as spec data. Changing it needs a spec note.

## Contract tests (CI)

- Canned package + canned gold files → exact hit@5 / hit@10 booleans.
- `eval.json` row without `source_files` is rejected.
- Fetch mapper drops an `answer` key if the CSV row has one.

No live searcher in CI. Pass a canned package into `hit_at_k`.

## Manual live check

1. Confirm Plan 3 search works on one question.
2. Run fetch if `eval.json` is missing.
3. Run eval.
4. Confirm a printed table with qid, hit@5, hit@10, rounds, tool_calls.
5. Open the MLflow experiment. Confirm one run per qid, or confirm the notebook warned that tracing was skipped.

Pass: table prints, metrics match the package contract. Fail: eval calls the parent, answers appear in git, notebook requires MLflow success to print the table.

## Done when

You have a screenshot-ready table and, if tracing worked, an MLflow run list. CI contract tests pass. The blog story is complete.
